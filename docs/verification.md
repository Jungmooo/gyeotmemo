# 곁메모 검증 기록

사용자 사례 두 가지를 회귀 검증으로 추가해 기존 버전의 실패를 재현한 뒤 수정했습니다. 저장·복구·일정 검증 15개 묶음과 기존 WPF 레이아웃 회귀 검증을 통과했습니다.

- `2시 반`이 자동으로 02:30으로 확정되는 문제 수정
- 오전·오후 없는 1~12시와 반 시각에 대해 두 후보를 계산하고 선택 전 알림 보류
- 오전/오후 선택, 자정 경계, 선택 대기 및 확정 상태 저장·재실행 확인
- 설명만 수정하면 선택 유지, 모호한 시각을 바꾸면 다시 선택 요청
- `26일 목요일 오후 4시 교수님 미팅`을 2026-11-26 16:00으로 인식
- 날짜·요일 불일치 시 확인 안내, 요일만 있는 일정도 가까운 해당 요일로 인식
- 기존 모호한 일정은 원래 날짜를 보존하면서 선택 대기로 전환
- 기존의 명확한 일정과 알림 전송 상태 보존, 이전에 거부된 요일 포함 일정 재인식

## 1.1.0 일정 알림 (2026-11-25)

- 저장·복구 검증 8개와 추가 알림 검증 4개 묶음 통과
- 한글·숫자 날짜, 오늘·내일·모레, 오전·오후, 24시간제, 반 시각, 월·연도 경계 확인
- 잘못된 날짜와 시간, 기간 표현, 여러 시간과 반복 표현의 오인식 방지 확인
- 상대 날짜의 자정 후 고정, 정확한 30분 경계, 시작·절전 복귀 시 30분 이내 일정 알림 확인
- 완료·편집 중 항목 알림 억제, 알림 전송 상태 저장, 설명 수정과 일정 변경, 날짜 제거 시 동작 확인
- 기존 버전 1 저장 데이터의 메모 내용을 유지하면서 일정 정보 추가 확인
- 기존 메모 영역 드래그 확대·축소, 크기 저장 복원, 최소 창 크기 레이아웃 검증 통과
- 실제 Windows에서 앱을 최소화한 상태로 30분 전 시각을 기다려 자동 알림 전송 및 Windows 알림 표시 이벤트 확인

Windows 알림 설정이나 방해 금지 상태에 따라 표시가 제한될 수 있습니다. 앱 실행 중에 알림을 확인하며, 종료 중인 앱이나 절전 중인 PC를 자동으로 깨우는 예약 작업은 생성하지 않습니다.

## 자동 검증

배포할 GyeotMemo.exe의 --self-test를 별도 테스트 폴더에서 실행했습니다. 종료 코드 0, 아래 8개 검증 항목이 모두 통과했습니다.

1. 빈 목록으로 시작하며 항상 위 고정이 기본값인지 확인
2. 한글·유니코드, 여러 줄 메모, 작성 중인 입력, 완료 상태, 위치·크기·메모 영역 높이·고정 상태 저장 및 복원
3. 임시 파일을 통한 저장, 백업 생성, 손상 파일 보관, 백업 복원 후 다시 저장
4. 더 새로운 저장 형식을 덮어쓰지 않고 보존
5. 백업 없는 손상 파일을 보관한 후 빈 메모 시작
6. 저장 형식 필드가 잘못된 파일에서 시작 오류 없이 복구
7. 파일 잠금으로 저장 실패 시 기존 내용 유지 및 임시 파일 정리
8. 여러 항목 삭제, 연속 삭제 되돌리기, 원래 위치 복원, 순서 변경 후 저장·복원

## 실제 Windows 화면 검증

- 실행과 초기 빈 화면
- 한글 입력 및 Enter로 두 항목 추가
- 완료 체크, 취소선, 완료 수와 진행 표시
- 수정 버튼으로 편집 진입, 글 수정 후 Enter로 확정
- 손잡이 드래그로 항목 순서 변경
- 고정 버튼 해제 및 저장된 설정 확인
- 여러 줄 자유 메모 입력
- 창 크기 축소 시 목록 스크롤과 메모 영역 표시
- 종료 후 다시 실행하여 내용, 완료 상태, 항목 순서, 창 크기와 고정 설정 복원
- 새 버전 저장 파일을 읽기 전용으로 보호하고, 창 이동 및 종료 후에도 원본 내용 유지

UI 검증용 내용과 데이터는 배포 폴더에 넣지 않았습니다. 삭제와 되돌리기는 별도 자동 검증으로 확인했습니다. 다양한 PC, 독점 전체 화면과 모든 모니터/DPI 구성까지 검증한 것은 아닙니다.

## 1.0.1 메모 영역 크기 조절 수정 (2026-10-28)

수정 전에는 조절 막대가 고정 높이의 완료 정리 줄과 메모 줄을 대상으로 삼았습니다. 재현 시 완료 정리 줄이 24.8에서 0으로 줄어드는 동안 실제 메모 입력창은 96.8로 유지되었습니다.

할 일 목록과 완료 정리 줄을 하나의 영역으로 묶어 메모 영역과 직접 공간을 나누도록 수정했습니다. 미리보기 대신 실제 배치를 드래그 중에 갱신하며, 창의 내부 높이에 맞춰 메모 영역의 최대 높이를 제한합니다. 저장된 높이를 복원할 때 초기 배치의 일시적인 크기에 의해 줄어들지 않도록 했습니다.

배포하는 1.0.1 실행 파일에서 저장·복구 검증 8개와 추가 레이아웃 회귀 검증을 통과했습니다.

- 100만큼 위로 드래그: 메모 줄 136 → 236, 실제 입력창 96.8 → 196.8, 완료 정리 줄과 전체 창 높이는 유지
- 드래그 중에도 실제 입력창 높이 변경 확인
- 아래로 드래그하여 실제 입력창이 다시 줄어드는 것 확인
- 최대 높이까지 확대한 후 재실행: 높이 304 유지, 여러 줄 메모 내용 유지
- 전체 창을 최소 크기로 줄여도 메모 입력창이 하단 상태 표시 영역 안에 유지
- 실제 Windows 화면에서 여러 줄 메모를 입력하고 마우스 드래그로 더 많은 줄이 보이는 것 확인

소스의 `tests/run-layout-tests.ps1`로 같은 WPF 드래그 처리와 높이 복원 검증을 재실행할 수 있습니다.

## macOS 1.0.1 (2026-10-28)

macOS 26.6 (Apple silicon)에서 `mac/build.sh`로 만든 유니버설 앱과 `.dmg`를 검증했습니다.

- `--self-test`: Windows와 같은 저장·복구 8개 항목 통과 (arm64, Rosetta를 통한 x86_64 모두). macOS에는 강제 파일 잠금이 없어 7번은 쓰기 금지 폴더로 저장 실패를 재현했습니다.
- `--layout-test`: 실제 창을 화면 밖 공간에 띄워 검증, 9개 항목 통과
  - 메모 손잡이를 100 위로 드래그: 메모 영역 136 → 236, 창 높이 유지 / 아래로 60 드래그: 176
  - 최소 82 ~ 최대 310(380×650 창 기준)으로 제한, 재실행 후 최대 높이 310 복원
  - 창을 최소 크기 330×490으로 줄여도 메모가 하단 상태 표시줄 위에 유지되고, 창을 다시 키우면 요청한 높이로 돌아옴
  - 필드 편집기를 통한 입력: Return으로 할 일 추가(앞뒤 공백 제거, 빈 입력 무시), 인라인 수정 Return 확정 · Escape와 빈 글 취소
  - ⌥↑ 순서 변경, 완료 정리 후 ⌘Z로 원래 위치 복원, 고정 해제, 작성 중 입력과 함께 재실행 복원
- 실제 화면: 저장된 창 위치·크기·고정(floating 레벨) 복원, 한글·이모지·여러 줄 할 일 줄바꿈, 완료 취소선, 진행 표시, 메모 표시 확인
- 같은 data 폴더로 두 번째 실행 시 새 창을 열지 않고 종료
- `.dmg`: `hdiutil verify` 통과, 마운트한 이미지 안의 앱 서명 검증(`codesign --verify --deep --strict`)과 두 검증 모드 통과

Apple 공증은 받지 않았습니다. 마우스로 하는 손잡이 드래그·버튼 클릭과 Intel Mac 실기기, macOS 13·14 실기기 화면은 직접 확인하지 않았습니다.
