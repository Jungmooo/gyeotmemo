# 곁메모 검증 기록

검증일: 2026-10-27

## 자동 검증

배포할 GyeotMemo.exe의 --self-test를 별도 테스트 폴더에서 실행했습니다. 종료 코드 0, 아래 8개 검증 항목이 모두 통과했습니다.

1. 빈 목록으로 시작하며 항상 위 고정이 기본값인지 확인
2. 한글·유니코드, 여러 줄 메모, 작성 중인 입력, 완료 상태, 위치·크기·메모 영역 높이·고정 상태 저장 및 복원
3. 임시 파일을 통한 저장, 백업 생성, 손상 파일 보관, 백업 복원 후 다시 저장
4. 더 새로운 저장 형식을 덮어쓰지 않고 보존
5. 백업 없는 손상 파일을 보관한 후 빈 메모 시작
6. 저장 형식 필드가 잘못된 파일에서 시작 오류 없이 복구
7. 파일 잠금으로 저장 실패 시 기존 내용 유지 및 임시 파일 정리
8. 여러 항목 삭제, 연속 삭제 되돌리기, 원래 위치 복원, 순서 변경 후 저장·복원

## 실제 Windows 화면 검증

- 실행과 초기 빈 화면
- 한글 입력 및 Enter로 두 항목 추가
- 완료 체크, 취소선, 완료 수와 진행 표시
- 수정 버튼으로 편집 진입, 글 수정 후 Enter로 확정
- 손잡이 드래그로 항목 순서 변경
- 고정 버튼 해제 및 저장된 설정 확인
- 여러 줄 자유 메모 입력
- 창 크기 축소 시 목록 스크롤과 메모 영역 표시
- 종료 후 다시 실행하여 내용, 완료 상태, 항목 순서, 창 크기와 고정 설정 복원
- 새 버전 저장 파일을 읽기 전용으로 보호하고, 창 이동 및 종료 후에도 원본 내용 유지

UI 검증용 내용과 데이터는 배포 폴더에 넣지 않았습니다. 삭제와 되돌리기는 별도 자동 검증으로 확인했습니다. 다양한 PC, 독점 전체 화면과 모든 모니터/DPI 구성까지 검증한 것은 아닙니다.

## 1.0.1 메모 영역 크기 조절 수정 (2026-10-28)

수정 전에는 조절 막대가 고정 높이의 완료 정리 줄과 메모 줄을 대상으로 삼았습니다. 재현 시 완료 정리 줄이 24.8에서 0으로 줄어드는 동안 실제 메모 입력창은 96.8로 유지되었습니다.

할 일 목록과 완료 정리 줄을 하나의 영역으로 묶어 메모 영역과 직접 공간을 나누도록 수정했습니다. 미리보기 대신 실제 배치를 드래그 중에 갱신하며, 창의 내부 높이에 맞춰 메모 영역의 최대 높이를 제한합니다. 저장된 높이를 복원할 때 초기 배치의 일시적인 크기에 의해 줄어들지 않도록 했습니다.

배포하는 1.0.1 실행 파일에서 저장·복구 검증 8개와 추가 레이아웃 회귀 검증을 통과했습니다.

- 100만큼 위로 드래그: 메모 줄 136 → 236, 실제 입력창 96.8 → 196.8, 완료 정리 줄과 전체 창 높이는 유지
- 드래그 중에도 실제 입력창 높이 변경 확인
- 아래로 드래그하여 실제 입력창이 다시 줄어드는 것 확인
- 최대 높이까지 확대한 후 재실행: 높이 304 유지, 여러 줄 메모 내용 유지
- 전체 창을 최소 크기로 줄여도 메모 입력창이 하단 상태 표시 영역 안에 유지
- 실제 Windows 화면에서 여러 줄 메모를 입력하고 마우스 드래그로 더 많은 줄이 보이는 것 확인

소스의 `tests/run-layout-tests.ps1`로 같은 WPF 드래그 처리와 높이 복원 검증을 재실행할 수 있습니다.
